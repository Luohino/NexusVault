# Security Policy

## 1. Supported Versions
We actively support and provide security updates for the latest stable release of NexusVault.

## 2. Reporting a Vulnerability
If you discover a security anomaly, data leak risk, or system vulnerability, please do not disclose it publicly (e.g., via GitHub Issues). 

Contact **Luohino** directly to ensure a coordinated and safe resolution:
**Email:** lutervyn@gmail.com

## 3. Safe Harbor
We promise not to pursue legal action against researchers who discover and report vulnerabilities in NexusVault in good faith, provided that:
- You do not perform actions that degrade the service for other users (e.g., DoS).
- You do not access, modify, or delete data belonging to other users.
- You provide us a reasonable amount of time to resolve the issue before any public disclosure.

## 4. Our Response
We take security seriously. For all critical security reports, we aim to:
- Acknowledge the report within 24-48 hours.
- Provide a timeline for a fix or mitigation.
- Credit the researcher (if desired) once the fix is deployed.

## 4. Security Philosophy
NexusVault is built on the principle of **Isolation and Integrity**. We utilize Clerk for robust session management and Supabase RLS (Row Level Security) to ensure that your private data remains yours.
